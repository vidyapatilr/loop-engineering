Understanding Agent Loops

An agent loop is a process where information is sent to a model, actions are taken based on the model's outputs, and the results are fed back into the model until a goal is reached. This is different from a single request because it allows for more complex tasks to be handled step-by-step, ensuring better accuracy and context retention.

Context -> Model Response -> Actions Taken -> Updated Context -> Repeat

Why Use an Agent Loop?

Using an agent loop instead of a single request can help in several ways:

  • Improved Accuracy: Repeatedly updating context can refine results.
  • Complex Tasks: Break down large questions into manageable steps.
  • Context Retention: Maintain critical details throughout interactions.

What Can Go Wrong?

If not designed carefully, agent loops can lead to:

  • Runaway Costs: If a loop runs too many times, it can become expensive.
  • Losing Context: Important information might be forgotten between steps.
  • No Verification: Outputs might not be validated, leading to incorrect results.

Worked Example

Scenario: Planning a Dinner Party

Let's say you want to plan a dinner party for 5 people with a budget of $150.

  1. Context: You start with the information: “Plan a dinner party for 5 people with a budget of $150.”
  2. Model Response: The model suggests: “Buy ingredients for pasta, salad, and dessert for $120.”
  3. Actions Taken: You decide to buy pasta ($30), salad ingredients ($25), and a dessert mix ($15).
  4. Updated Context: Now you have: “Spent $70 on the main ingredients, with $80 remaining.”
  5. Repeat: You ask the model: “What else can I buy with $80?” The model suggests additional drinks and snacks.

This process continues until you've finalized your dinner plan.
